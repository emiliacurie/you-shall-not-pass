## Repository work: You Shall Not Pass

Use the `you-shall-not-pass` skill before repository edits or Git mutations, including
requests such as “fix the footer,” “save this,” “upload it,” or “start over.”

- Work on a separate branch; read the skill's policy for protected branches and actions.
- Shared work goes through a pull request. Opening one is not permission to merge it.
- Keep private credentials out of commits; inspect actual staged contents.
- Reuse specific authorization for the current task. Do not ask repeatedly for routine
  steps or an upload already requested.
- Before discarding work, name what will be lost and obtain approval for that scope if
  it has not already been given. A vague cleanup request or a backup is not approval.
- Explain a block and follow the documented safe path. Do not bypass checks or edit
  the policy merely to finish a blocked operation.

These instructions guide the agent. Executable checks and server restrictions must be
configured separately; consult the skill's setup and coverage documents.
